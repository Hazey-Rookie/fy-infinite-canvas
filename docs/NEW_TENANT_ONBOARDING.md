# 新企业接入与访问地址操作手册

本文适用于平台超管为新的飞书企业接入 FY Canvas。推荐使用“一次性企业接入邀请”完成认证：企业负责人自行创建飞书自建应用，并在受保护的接入页面提交应用信息；平台不要求通过聊天或邮件传递 `App Secret`。

## 一、准备信息

平台超管和新企业负责人分别准备以下信息：

| 角色 | 需要准备 |
| --- | --- |
| 平台超管 | 已部署并可访问的 FY Canvas 地址，例如 `https://canvas.example.com`；平台超管账号 |
| 新企业负责人 | 该企业飞书开放平台管理员权限；能够创建、配置和发布飞书自建应用 |

本文用 `<FY_ORIGIN>` 表示实际访问源，例如 `https://canvas.example.com`。不要把末尾 `/` 重复拼接到路径中。

## 二、新企业配置飞书 SSO 应用

由新企业负责人在飞书开放平台操作：

1. 进入飞书开放平台，创建一个企业自建应用，选择支持网页或 OAuth 登录的能力。
2. 在应用安全设置中登记 OAuth 重定向地址：

   ```text
   <FY_ORIGIN>/auth/callback
   ```

   例如：

   ```text
   https://canvas.example.com/auth/callback
   ```

   本地联调和生产环境使用不同地址时，必须分别登记；如果存在多个正式域名或端口，也必须分别登记。接入页默认填入当前页面源对应的回调地址，必须与飞书后台登记的地址完全一致。

3. 为应用开通并发布以下能力，权限名称以飞书开放平台当前界面为准：
   - 用户身份登录或 OAuth 登录能力；
   - 通讯录部门和用户只读权限，用于同步企业组织架构；
   - 企业信息只读权限（推荐开通，用于自动读取企业名称）。

   不需要为本接入流程开通多维表格权限。

4. 发布应用版本，并确认应用的可用范围覆盖需要使用 FY Canvas 的企业成员。
5. 记录该应用的 `App ID` 和 `App Secret`。`App Secret` 属于敏感凭据，不要写入工单、群聊、邮件或 Git；后续直接在一次性接入页面中填写。

## 三、平台超管生成企业接入邀请

1. 平台超管访问 `<FY_ORIGIN>/`，完成飞书登录。
2. 打开“组织与权限”页面，在“企业列表”区域点击“生成企业接入邀请”（加号按钮）。
3. 填写“企业备注”，用于超管识别本次邀请；选择邀请有效期。默认有效期为 1 小时，可按页面提供的选项调整。
4. 点击“生成一次性链接”，复制页面生成的邀请地址。
5. 通过受控、可信的渠道把邀请地址发给新企业负责人。邀请地址包含一次性令牌，不能公开发布、转发给无关人员或重复使用。

邀请地址的形式如下，仅作格式示例：

```text
<FY_ORIGIN>/static/tenant-onboarding.html?token=<一次性令牌>
```

邀请令牌只允许成功接入一次，过期或使用后再次打开会被拒绝。企业负责人不需要把 `App Secret` 回传给平台超管。

## 四、新企业提交认证信息

新企业负责人打开超管发送的邀请地址后：

1. 在“企业标识”中填写本企业唯一标识。它是系统内部识别企业的稳定键，不是企业显示名称；只能使用小写字母、数字、下划线和连字符，首字符须为字母或数字，最多 64 个字符，例如 `acme`。同一平台已存在的标识不能重复，接入完成后应视为不可随意更改。
2. 填写飞书应用的 `App ID` 和 `App Secret`。
3. 检查“OAuth 回调地址”。通常保持接入页自动填写的 `<FY_ORIGIN>/auth/callback`，不要改成租户专用路径。
4. 点击“验证并完成企业接入”。系统会验证应用凭据、企业身份和组织读取权限，并使用飞书企业名称建立租户档案。
5. 页面显示“已完成接入验证”后，点击页面提供的登录入口，或把成功页面告知平台超管。

如果验证失败，先根据页面提示检查：应用是否已发布、回调地址是否逐字符一致、通讯录权限是否已审批、应用是否授权给当前企业。验证失败不会消耗邀请令牌，可以在有效期内修正配置后重试。

## 五、平台超管确认并完成初始化

1. 返回“组织与权限”页面并刷新企业列表，确认新企业显示真实企业名称，且状态为“已完成飞书认证”。
2. 点击新企业名称，按需点击“同步成员”，确认部门和成员数量能够正常加载。
3. 在“成员授权”中为需要管理本企业权限的成员分配内置 `admin` 角色。`admin` 即企业管理员，只有平台超管可以授予或撤销。
4. 用新企业成员账号验证登录、组织权限菜单和默认 `member` 权限。企业管理员只能管理本企业普通成员，不能管理角色定义、外部账号或其他企业。

## 六、发送企业访问地址

### 推荐地址：统一入口

向企业成员发送：

```text
<FY_ORIGIN>/
```

用户打开后在登录页选择所属企业，再点击“飞书登录”。这是日常使用和公告中应使用的地址，所有企业共用同一个入口。

### 兼容地址：指定企业登录入口

如确实需要在链接中预先指定企业，可使用：

```text
<FY_ORIGIN>/t/<tenant_slug>/login
```

其中 `<tenant_slug>` 默认就是企业接入时的企业标识，因此企业标识会影响这个兼容地址；如果标识写错，后续应重新选择未占用的标识并重新接入。该地址仅用于兼容或定向入口；新链接仍建议发送统一入口 `<FY_ORIGIN>/`。不要把 `/auth/callback` 地址发送给用户，它是飞书回调地址，不是登录入口。

## 七、常见问题

### 提示“回调地址不一致”

确认飞书后台登记的是完整地址 `<FY_ORIGIN>/auth/callback`，协议、域名、端口和路径都必须一致；不要把邀请地址中的 `/static/tenant-onboarding.html?token=...` 当作回调地址。

### 提示“读取企业名称失败”

通常表示 `App ID` 和 `App Secret` 已经有效，但应用没有企业信息或通讯录读取权限，或应用版本尚未发布/授权。补齐权限并发布后，在原邀请有效期内重试。

### 提示“企业标识已存在”

换用未被其他企业使用的标识。标识只允许小写字母、数字、下划线和连字符。

### 邀请链接无效、已使用或已过期

请平台超管重新生成邀请。不要尝试修改令牌参数，也不要复用已经成功接入的链接。

## 八、安全要求

- `App Secret`、会话密钥和真实用户标识不得提交到代码仓库或公开文档。
- 邀请链接等同于一次性接入凭据，只发送给确认过身份的企业负责人。
- 企业接入完成后，平台超管应及时确认企业名称、成员同步和管理员角色，避免把权限授予错误企业。
- HTTPS 正式环境应使用 `https://` 回调地址，并按部署要求开启安全 Cookie；本地 HTTP 联调地址只用于开发测试。
