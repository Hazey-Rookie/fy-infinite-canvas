# 飞书 SSO、组织与权限配置

本文档只保留可公开的配置结构。`<...>` 占位符必须在部署时从本机私有配置中替换，真实密钥、用户标识、资源标识、组织规模和内网地址不得写入 Git。

## 1. 当前权限规则

- 所有本地和线上用户都必须通过飞书 SSO 登录，不存在免登录开发模式。
- 首次登录只创建画布会话，不会自动向多维表格新增成员记录。
- 应用从当前飞书企业通讯录同步部门和人员；手动刷新会立即重新同步，普通访问缓存 60 秒。
- `FY_SUPER_ADMIN_IDS` 指定默认超管；不要在源码中记录其姓名或真实用户标识。
- 其他组织成员即使不在授权表中也可登录，默认角色固定为 `member`。
- 只有默认超管可以在“组织与权限”中新增、修改、停用或移除成员授权，以及维护角色权限。
- 移除成员授权只删除多维表格中的授权记录，该用户仍在组织架构中，并恢复为默认 `member`。
- 默认超管始终为启用状态和 `admin` 角色，不能通过成员表降级、停用或移除。

## 2. 创建并配置企业应用

1. 在飞书开放平台创建或使用“扶摇”企业的自建应用，取得 `App ID` 和 `App Secret`。
2. 启用网页应用能力，并在安全设置中登记以下两个重定向 URL：

   ```text
   http://127.0.0.1:8000/auth/callback
   http://canvas.example.com:808/auth/callback
   ```

3. 发布应用版本，并确保应用可用范围覆盖所有需要使用画布的组织成员。
4. 为应用申请并审批登录身份、通讯录部门与用户读取、多维表格记录读写权限。
5. 确保该企业应用可以访问生产环境的画布授权多维表格。表格所有者与应用访问权限相互独立，必须在飞书侧完成授权和可见范围配置。

本地与线上共用同一个应用时，服务会按当前访问地址选择同源回调，并将该地址绑定到签名登录状态；换取令牌时继续使用同一个地址。

## 3. 创建画布授权多维表格

在生产环境指定账号下创建一个多维表格应用，并建立“成员”和“角色”两张数据表。字段名称需与下表完全一致。

部署时填写以下占位符，实际值只保存在本机 `API/.env`：

```text
多维表格：<BITABLE_NAME>
app_token：<FEISHU_BITABLE_APP_TOKEN>
成员表 table_id：<FEISHU_BITABLE_MEMBERS_TABLE_ID>
角色表 table_id：<FEISHU_BITABLE_ROLES_TABLE_ID>
```

### 成员表

| 字段 | 推荐类型 | 用途 |
| --- | --- | --- |
| `Open ID` | 单行文本 | 飞书用户主匹配键 |
| `User ID` | 单行文本 | 企业内用户 ID |
| `Name` | 单行文本 | 姓名 |
| `Email` | 单行文本 | 邮箱 |
| `Department IDs` | 多行文本 | JSON 部门 ID 数组 |
| `Role` | 单行文本 | 角色标识 |
| `Status` | 单行文本 | `active` 或 `disabled` |
| `Updated At` | 数字或日期 | 毫秒时间戳 |

成员表仅保存管理员明确操作产生的授权覆盖。不要预先导入整个组织，也不要配置登录自动新增流程。

### 角色表

| 字段 | 推荐类型 | 用途 |
| --- | --- | --- |
| `Role` | 单行文本 | 唯一角色标识 |
| `Display Name` | 单行文本 | 显示名称 |
| `Permissions` | 多行文本 | JSON 菜单权限数组 |
| `System` | 复选框 | 是否为系统角色 |
| `Updated At` | 数字或日期 | 毫秒时间戳 |

系统内置 `member`、`admin`、`guest` 三个角色。角色表中的同名记录可覆盖其菜单权限，也可保存自定义角色。

### 文档应用写权限

应用开通 `bitable:app` 后仍不一定能修改指定账号空间中的表格。还必须在目标表格的更多菜单中选择“添加文档应用”，将对应企业应用设为可编辑。

普通“添加协作者”只搜索用户、群组、部门或用户组，无法添加企业应用。未添加文档应用时，读取表格可能正常，但新增、修改、删除记录会返回飞书 `403/91403`。

## 4. 配置服务

将配置写入不会提交到 Git 的 `API/.env`：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_REDIRECT_URIS=http://127.0.0.1:8000/auth/callback,http://canvas.example.com:808/auth/callback
FY_SESSION_SECRET=请使用独立的高强度随机值
FY_COOKIE_SECURE=false
FY_SUPER_ADMIN_IDS=ou_xxx
FEISHU_BITABLE_APP_TOKEN=bascn_xxx
FEISHU_BITABLE_MEMBERS_TABLE_ID=tbl_xxx
FEISHU_BITABLE_ROLES_TABLE_ID=tbl_xxx
```

`FY_SUPER_ADMIN_IDS` 必须填写默认超管的 `open_id` 或 `user_id`，也可以同时填写两个标识并用英文逗号分隔。系统不会根据姓名判断超管，也不会将其他飞书企业管理员自动提升为画布超管。

当前两个回调均为 HTTP，因此示例使用 `FY_COOKIE_SECURE=false`。以后切换到 HTTPS 域名时，需要在飞书开放平台增加对应的 `/auth/callback` 地址，并设置 `FY_COOKIE_SECURE=true`。

旧配置 `FEISHU_REDIRECT_URI` 仍可兼容单地址部署，但本地与线上同时使用时应配置 `FEISHU_REDIRECT_URIS`。

## 5. 联调检查

1. 分别访问 `http://127.0.0.1:8000/` 和生产环境地址，确认未登录时都跳转登录页。
2. 在两个地址分别完成登录，确认飞书没有提示回调地址不一致。
3. 用默认超管账号登录，确认 `/api/auth/me` 返回 `role=admin`、`is_super_admin=true`。
4. 用其他组织成员登录，确认未自动产生成员表记录，且默认返回 `role=member`。
5. 进入“组织与权限”刷新，确认部门与人员来自当前飞书企业通讯录。
6. 由默认超管修改一名成员为 `guest`，确认成员表新增或更新对应记录，且该成员只能查看。
7. 移除该成员授权，确认多维表格记录被删除，页面中该成员恢复为默认 `member`。
8. 尝试停用、降级或移除默认超管，确认前端不可操作且接口拒绝。

生产环境的验证结果、组织规模和故障记录只保存在本机私有交接文档中，不得回填到本文件。

应用密钥、会话密钥、真实用户标识和多维表格标识不得提交到 Git。
