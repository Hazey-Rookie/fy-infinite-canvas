# 飞书 SSO、组织与权限配置

本文档只保留可公开的配置结构。`<...>` 占位符必须在部署时从本机私有配置中替换，真实密钥、用户标识、资源标识、组织规模和内网地址不得写入 Git。

## 1. 当前权限规则

- 企业成员通过飞书 SSO 登录；不在企业通讯录中的协作者可使用应用本地账号登录。
- 首次登录只创建画布会话，不会自动创建成员授权覆盖。
- 应用从当前飞书企业通讯录同步部门和人员；手动刷新会立即重新同步，普通访问缓存 60 秒。
- `FY_SUPER_ADMIN_IDS` 指定默认超管；不要在源码中记录其姓名或真实用户标识。
- 其他组织成员即使不在授权表中也可登录，默认角色固定为 `member`。
- 只有默认超管可以在“组织与权限”中新增、修改、停用或移除成员授权，以及维护角色权限。
- 移除成员授权只删除应用权限库中的授权覆盖，该用户仍在组织架构中，并恢复为默认 `member`。
- 默认超管始终为启用状态和 `admin` 角色，不能通过成员表降级、停用或移除。
- 外部账号不映射为飞书成员，默认使用 `guest` 角色；只有默认超管可以创建、改权、重置密码或停用。

## 2. 创建并配置企业应用

1. 在飞书开放平台创建或使用“扶摇”企业的自建应用，取得 `App ID` 和 `App Secret`。
2. 启用网页应用能力，并在安全设置中登记以下两个重定向 URL：

   ```text
   http://127.0.0.1:3000/auth/callback
   http://canvas.example.com:808/auth/callback
   ```

3. 发布应用版本，并确保应用可用范围覆盖所有需要使用画布的组织成员。
4. 为应用申请并审批登录身份、通讯录部门与用户读取权限；不需要多维表格权限。

本地与线上共用同一个应用时，服务会按当前访问地址选择同源回调，并将该地址绑定到签名登录状态；换取令牌时继续使用同一个地址。

## 3. 应用权限库

成员授权覆盖、角色定义和外部账号统一保存在 `FY_AUTH_DB_PATH` 指向的 SQLite 数据库，默认是 `data/fy_auth.db`。飞书只负责登录身份验证和企业通讯录读取，运行时不会访问 `/bitable/v1/*`。

系统内置 `member`、`admin`、`guest` 三个角色；管理员在“组织与权限”页面维护角色和成员授权。旧的 Bitable 配置字段可以保留在私有环境中作为迁移参考，但不会被读取或写入。

## 4. 配置服务

将配置写入不会提交到 Git 的 `API/.env`：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_REDIRECT_URIS=http://127.0.0.1:3000/auth/callback
FY_SESSION_SECRET=请使用独立的高强度随机值
FY_COOKIE_SECURE=false
FY_SUPER_ADMIN_IDS=ou_xxx
FY_LOCAL_AUTH_ENABLED=true
FY_AUTH_DB_PATH=data/fy_auth.db
FY_PERMISSION_STORE=local
```

`FY_SUPER_ADMIN_IDS` 必须填写默认超管的 `open_id` 或 `user_id`，也可以同时填写两个标识并用英文逗号分隔。系统不会根据姓名判断超管，也不会将其他飞书企业管理员自动提升为画布超管。

当前两个回调均为 HTTP，因此示例使用 `FY_COOKIE_SECURE=false`。以后切换到 HTTPS 域名时，需要在飞书开放平台增加对应的 `/auth/callback` 地址，并设置 `FY_COOKIE_SECURE=true`。

旧配置 `FEISHU_REDIRECT_URI` 仍可兼容单地址部署，但本地与线上同时使用时应配置 `FEISHU_REDIRECT_URIS`。

## 5. 联调检查

1. 访问 `http://127.0.0.1:3000/` 和生产环境地址，确认未登录时都跳转登录页。
2. 在两个地址分别完成登录，确认飞书没有提示回调地址不一致。
3. 用默认超管账号登录，确认 `/api/auth/me` 返回 `role=admin`、`is_super_admin=true`。
4. 用其他组织成员登录，确认未自动产生成员表记录，且默认返回 `role=member`。
5. 进入“组织与权限”刷新，确认部门与人员来自当前飞书企业通讯录。
6. 由默认超管修改一名成员为 `guest`，确认应用权限库新增或更新对应记录，且该成员只能查看。
7. 移除该成员授权，确认应用权限库覆盖被删除，页面中该成员恢复为默认 `member`。
8. 尝试停用、降级或移除默认超管，确认前端不可操作且接口拒绝。

## 6. 外部人员账号

登录页会在 `FY_LOCAL_AUTH_ENABLED=true` 时显示外部账号入口。默认超管进入“组织与权限”的“外部账号”页创建账号，填写账号、展示名称、初始密码、角色和到期日期；默认有效期为 30 天。密码只以 PBKDF2 摘要写入 `FY_AUTH_DB_PATH` 指向的 SQLite 文件。账号到期后会自动停用，超管可以调整到期日期、手动启停或永久删除账号。状态或角色变更会在下一次受保护请求立即生效。初始密码应通过独立安全渠道交付，应用不会发送邮件或在响应中回显密码。

如需紧急关闭本地账号入口，将 `FY_LOCAL_AUTH_ENABLED` 设为 `false` 并重启服务；已有本地会话仍会在下一次请求因账号状态校验而失效。

生产环境的验证结果、组织规模和故障记录只保存在本机私有交接文档中，不得回填到本文件。

应用密钥、会话密钥和真实用户标识不得提交到 Git。
