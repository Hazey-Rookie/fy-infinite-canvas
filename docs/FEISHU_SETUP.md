# 飞书 SSO、组织与权限配置

本文档只保留可公开的配置结构。`<...>` 占位符必须在部署时从本机私有配置中替换，真实密钥、用户标识、资源标识、组织规模和内网地址不得写入 Git。

## 1. 当前权限规则

- 企业成员使用飞书 SSO；外部协作者使用平台管理员创建的租户级本地账号。两类会话都写入并校验租户边界。
- 所有企业成员使用同一个应用根地址。未登录时先在统一登录页选择所属企业，再由系统选择该企业的飞书应用发起授权；用户无需输入租户专用路径。
- 每个企业使用独立自建应用时，企业选择不能省略：飞书授权 URL 在识别用户身份前就要求确定 `App ID`。若要求一个按钮直接识别所有企业，必须改为由平台统一维护并向各企业发布同一个应用。
- 首次登录创建租户绑定的画布会话，并将成员目录资料同步到应用本地权限库。
- 应用从当前飞书企业通讯录同步部门和人员；手动刷新会立即重新同步，普通访问缓存 60 秒。
- `FY_SUPER_ADMIN_IDS` 指定默认超管；不要在源码中记录其姓名或真实用户标识。
- 其他组织成员即使不在授权表中也可登录，默认角色固定为 `member`。
- 平台超管可以跨企业管理租户、角色定义和外部账号；内置 `admin` 角色即企业管理员，只能在所属租户内查看并修改普通成员授权。
- 平台超管可在“组织与权限”页面新增企业并填写该企业的飞书 App ID、App Secret、回调地址；配置写入私有 `API/.env`，页面和接口不会返回 App Secret。
- 平台超管可选择企业手动同步通讯录、通过分配 `admin` 角色设置该企业管理员、停用或解除企业；解除企业时系统至少保留一个企业。
- 新企业推荐使用“生成企业接入邀请”：平台生成一次性、限时令牌链接，企业负责人自行创建和维护飞书自建应用，在邀请页提交认证信息；平台只负责验证应用、建立租户档案和后续权限管理。令牌只返回一次，数据库不保存明文令牌。
- 若接入页提示“已验证飞书应用身份，但读取企业名称失败”，表示 App ID/Secret 有效，但应用还不能读取通讯录根部门；请开通通讯录部门与用户读取权限并发布/授权应用后重试。
- 移除成员授权只删除应用本地授权覆盖，该用户仍在组织架构中，并恢复为默认 `member`；停用成员才会拒绝访问。
- 默认超管始终为启用状态和 `admin` 角色，不能通过成员表降级、停用或移除。
- 外部账号只能由平台超管创建，创建时必须选择目标租户和该租户角色；同一租户内登录名大小写不敏感且不可重复，不同租户可以使用相同登录名。账号密码只保存 PBKDF2 摘要，账号列表、状态和到期日期均按租户过滤。

## 2. 创建并配置企业应用

1. 每个接入企业分别创建自建应用，取得该企业的 `App ID` 和 `App Secret`。
2. 启用网页应用能力，并在安全设置中登记以下两个重定向 URL：

   ```text
   http://127.0.0.1:3000/auth/callback
   http://canvas.example.com:808/auth/callback
   ```

   以上仅为示例。实际部署时必须按用户访问的协议、域名和端口登记；企业接入页会自动以当前访问地址生成 `<当前 origin>/auth/callback`。如果同时开放多个端口，需要在飞书应用中分别登记多个回调地址。

3. 发布应用版本，并确保应用可用范围覆盖所有需要使用画布的组织成员。
4. 为每个应用申请并审批登录身份、通讯录部门与用户读取权限；不需要多维表格权限。

本地与线上共用同一个应用时，服务会按当前访问地址选择同源回调，并将该地址绑定到签名登录状态；换取令牌时继续使用同一个地址。

## 3. 配置服务

将配置写入不会提交到 Git 的 `API/.env`：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_REDIRECT_URIS=http://127.0.0.1:3000/auth/callback
FY_SESSION_SECRET=请使用独立的高强度随机值
FY_COOKIE_SECURE=false
FY_DEFAULT_TENANT_KEY=default
FY_SUPER_ADMIN_IDS=default:ou_xxx
FY_TENANTS_JSON=[{"tenant_key":"default","slug":"default","name":"示例企业","app_id":"cli_xxx","app_secret":"xxx","redirect_uris":["http://127.0.0.1:3000/auth/callback"],"enabled":true}]
FY_AUTH_DB_PATH=data/fy_auth.db
FY_LOCAL_AUTH_ENABLED=true
```

`FY_SUPER_ADMIN_IDS` 必须填写默认超管的 `open_id` 或 `user_id`，也可以同时填写两个标识并用英文逗号分隔。系统不会根据姓名判断超管，也不会将其他飞书企业管理员自动提升为画布超管。

当前两个回调均为 HTTP，因此示例使用 `FY_COOKIE_SECURE=false`。以后切换到 HTTPS 域名时，需要在飞书开放平台增加对应的 `/auth/callback` 地址，并设置 `FY_COOKIE_SECURE=true`。

旧配置 `FEISHU_REDIRECT_URI` 仍可兼容单地址部署，但本地与线上同时使用时应配置 `FEISHU_REDIRECT_URIS`。

## 4. 联调检查

1. 访问 `http://127.0.0.1:3000/` 和生产环境地址，确认未登录时都跳转登录页。
2. 在两个地址分别完成登录，确认飞书没有提示回调地址不一致。
3. 用默认超管账号登录，确认 `/api/auth/me` 返回 `role=admin`、`is_super_admin=true`。
4. 用其他组织成员登录，确认未自动产生成员表记录，且默认返回 `role=member`。
5. 进入“组织与权限”刷新，确认部门与人员来自当前飞书企业通讯录，权限来源显示为本地权限。
6. 由平台超管把成员角色设为 `admin`；该成员应立即看到“组织与权限”，只能修改本企业普通成员授权，不显示角色定义和外部账号页签，也不能授予或撤销 `admin`。
7. 修改一名成员为 `guest`，确认本地权限库更新且该成员只能查看。
8. 移除该成员授权，确认其恢复为默认 `member`；停用成员后确认其不能继续访问。
9. 尝试停用、降级或移除平台超管，确认前端不可操作且接口拒绝。
10. 平台超管新增第二个企业并完成认证，选择该企业同步成员，再为该企业设置管理员；确认管理员不能访问其他企业。
11. 尝试解除最后一个企业，确认接口返回失败且企业仍保留。
12. 平台生成一次性企业接入邀请；企业负责人打开链接填写自建应用信息，确认验证成功后令牌再次访问返回“已使用或已过期”。
13. 在“外部账号”页选择租户和角色创建账号；确认相同用户名在两个租户可分别登录，且修改或删除一个租户账号不会影响另一个租户。

生产环境的验证结果、组织规模和故障记录只保存在本机私有交接文档中，不得回填到本文件。

应用密钥、会话密钥、真实用户标识和权限数据库不得提交到 Git。
